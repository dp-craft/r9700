# Claude Haiku 5.5: when and how to use it

- **Date:** 2026-11-06 · **Kind:** manual, from measured runs
- **Model:** `claude-haiku-5-5`, run as a Claude Code `general-purpose` subagent (Agent tool, `model: haiku`, `effort: …`)
- **Compared with:** Ornith 1.5 35B-A3B on local Radiance; see [the Ornith manual](2026-11-06-0930-ornith-manual.md)
- **Evidence:** [use cases](2026-11-05-0814-ornith-use-cases.md), [document extraction, Ornith vs Haiku](2026-11-04-2207-sly-radiance-ornith-vs-haiku-high-effort.md), run data in `bench/runs/2026-11-05-0320-ornith-usecases/`

All numbers are `MEASURED` unless marked. Most come from one run per setting (n=1), on synthetic or repo fixtures.
Treat a score difference under 0.05 as a tie.

## In short

| | |
|---|---|
| **Use Haiku for** | Complete lists, paths, full configurations, incident lists, retyping text, synthesis across documents, blind grading |
| **Don't use it for** | Mechanical work a script can check (JSON questions, inventories, splitting, tests, small edits): Ornith ties there, costs no tokens and is faster |
| **Default effort** | `high`. `max` only for single-file judgement or grading jobs |
| **Never trust alone** | Final verdicts and critical flags: it still makes critical errors and overclaims |

## Strengths

| Area | Haiku | Ornith | Notes |
|---|---|---|---|
| Error classes in a 340k-token log | 21 of 21 | 16 of 21 (3 runs: 16, 16, 21) | Both found every planted fault |
| File paths in finding text | .969 at 9k, .941 at 33k | .756, .569 | Exact paths in notes: 15/15 and 39/45 (`high`), 43/45 (`medium`) |
| Full configuration in document notes | 8 of 8 | 4 of 8 | 4 reports |
| Incidents listed, 6 deep notes | 24 | 13 | Haiku `high` |
| Incidents told in footnotes or hedged text (e.g. "Exclude from delta interpretation", "may hold post-boundary files") | 4–6 of 6 notes per item | 0 of 3 | Same brief and fixture for both. Ornith didn't close the gap with any of 12 prompt or brief variants |
| Retyping a 6k document | 242 s, no loss | 480 s in its one clean run; 2 more didn't finish | |
| Valid conflicts across documents (synthesis) | S 1/1, L 4/4 | 0 valid | Haiku `high` |
| Facts on the exact line | 20/20, 30/30, 0 invented | 20/20, 30/30, 0 invented | A tie |

## Weaknesses

- **It still misses incidents:** 8–9 per 6 deep notes at `high`, 13 at `medium`.
- **Critical errors and overclaiming:** one critical error each at `high` and `medium`, in a 6-note deep grading pass. Examples:
  - calling one setting "the best point tested" when the report forbids ranking it
  - placing a gain in the wrong significance zone
  - recommendations with "best-graded" or "only"
- **Unstable judgement scores:** a recommendation scored 1 in one grading pass and 3 in the next.
- **Some labels are worse than Ornith's:** bug kind .718 vs .795 at 9k and .664 vs .723 at 33k. Severity is mixed: .41 vs .564 at 9k, .513 vs .445 at 33k.
- **It's slower and costs tokens:** on 15 paired tasks Haiku took 1.1–12.7× Ornith's wall time (median 3.9×). Remote latency is included.

## Effort levels

Effort is set per subagent call (`effort` on the Agent tool, which becomes `output_config.effort`).

| Effort | Generated tokens, 4 docs / 6 docs | Quality seen | Use for |
|---|---|---|---|
| `low` | 13.7k / 25.4k | At 4 docs it matched `high` on scripted scores with 42% fewer tokens. At 6 docs it broke the line format: all 30 FACT lines malformed, which breaks parsers | Small, format-light jobs only |
| `medium` | 17.7k / 31.0k (16–25% fewer than `high`) | Best paths (43/45), but the most incidents missed (13) | Path extraction |
| `high` | 23.5k / 36.7k | Best incident recall, best verdicts at 4 reports (12/12 and 11/12) | **Default** for notes, lists and synthesis |
| `max` | Not isolated against `high` on worker tasks | As a grader, closer to Opus than `high` on some fields (table below). One 4-file extraction (844 lines) at `max` read the files, then spent 128,000 thinking tokens without writing, 4 times in a row (3 automatic retries), and failed with no output | Grading, or one file at a time |

- **Tokens rise with effort; quality and wall time don't order the same way.** Remote wall times: 97–132 s at 4 docs, 149–209 s at 6 docs, not in effort order.
- **Cost seen per subagent call:**
  - one blind grading of one report at `max`: 227.5k subagent tokens, 462 s
  - a 303-line fact extraction at `high`: 113.6k tokens, 211 s
  - a 219-line one at `high`: 91.8k tokens, 138 s

## As a grader

Agreement with Opus on the same 40 notes, blind, same prompt (Opus pass 2 as the reference):

| Field | Haiku `high` exact | Haiku `max` exact |
|---|---|---|
| Verdict | 26 of 40 (38 within 1) | 28 of 38 |
| Config | 34 of 40 | 32 of 40 |
| Facts | 36 of 40 | 36 of 40 |
| Facts with wrong meaning | 37 of 40 | 37 of 40 |
| Unsupported incidents | 39 of 40 | 40 of 40 |
| Missed incidents | 21 of 40 (40 within 1) | 28 of 40 |

For comparison, Opus against itself, in two passes on 30 notes, gave the same verdict on 23 and was within one point on all 30.

- **It grades verdicts stricter than Opus:** by 0.30 points on average. Ornith's deep notes got 11 of 18 from Haiku and 14 from Opus.
- **Its critical flags need checking:** of 6 flags only Haiku raised, 1 was real and 5 didn't hold. It also missed 2 that Opus raised. Check every flag against the source before acting on it.
- **Grader noise is large:** the same notes scored 10/12 in one grading and 8/12 in another. Count a verdict gap under 4 of 18 as a tie.
- **Its scores don't replace Opus** for a published ranking. Use it to screen, and confirm what matters.

## How to use it efficiently

1. **Route by task** with the tables above. Send mechanical, checkable work to Ornith, and only the completeness- or judgement-heavy part to Haiku.
2. **Keep each call small:** one report or one file per subagent, especially at `max`. Ask for a compact structured result written to a file, not prose in the reply.
3. **Give fixed output fields** and check the format by script. This matters most at `low`.
4. **Check paths, numbers that decide something, and every critical flag** against the source. Haiku invents little (0 invented facts at `high`), but it overclaims in conclusions.
5. **Grading:** grade only the finalists, one report per grader, at most 3 graders in parallel. Use `max` only when a ranking depends on it.

## Risks

| Risk | Sign | Guard |
|---|---|---|
| Overclaiming in conclusions | "best", "only", "rules out" where the source hedges | Compare against the source's certainty words |
| False critical flags as a grader | A flag that names a sentence the source supports | Check each flag at its line |
| Broken format at `low` | Number and meaning merged in one field | Use `high` for large inputs; validate the fields |
| Reasoning runaway at `max` | The call ends with "exceeded the 128000 output token maximum" after turns that are all thinking; retries repeat it; no file written. Cause `INFERRED`: `max` effort plus a large synthesis in one call (n=1; effort and size not separated) | One file per call, or `high`: the same work split per file at `high` finished every time |
| Hidden context differences | A subagent has its own system prompt and tools, not the caller's | State paths and rules in the prompt; don't assume shared context |
