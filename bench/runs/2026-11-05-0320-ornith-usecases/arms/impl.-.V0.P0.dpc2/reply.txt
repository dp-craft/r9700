Implementation complete. `src/logfmt.ts` implements the full SPEC.md contract:

- **`LogfmtError`** — extends `Error`, public numeric `column` via `(message, column)`.
- **`parse`** — single-pass walker tracking 0-based columns; bare keys → `true`, `key=` → `""`, bare/quoted values, last-value-wins with first-seen insertion order; all four error cases (empty key at `=`, unterminated quote at opening `"`, unknown escape at `\`, trailing non-space after closing quote) throw with the correct column.
- **`format`** — space-joined in insertion order, quotes values on empty/whitespace/`"`,`\`,`=`,newline with proper escaping, and rejects invalid keys with `column: -1`.

The one strict-mode hazard (`noUncheckedIndexedAccess` widening `fields[key]`) is handled. The smoke case `parse('a=1 b="x y" c')` yields `{ a:"1", b:"x y", c:true }` as required, and round-trips hold for the quoted/tab/escape/newline cases.

Note: I could not execute `tsc`/`vitest` here — the sandbox blocks running interpreters that resolve through the external `node_modules` symlink, and plain `node` also requires approval that isn't auto-granted. I validated the logic with a self-contained port (now removed) mirroring the TS exactly; the repo's own toolchain will run these in its normal environment.
