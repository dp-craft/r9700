# radiance-image — native Radiance image upgrades

## Fixed facts (do not re-investigate)

- Image: `stilldeadcode/radiance:<tag>` · upstream + notes: https://codeberg.org/StillDeadcode/radiance (Codeberg, **not** GitHub)
- Serve: `stack/serve/radiance/serve_radiance.sh` — modes `start|stop|status|logs` (daemon, host network; stop is graceful SIGTERM-first + TIME_WAIT wait, silent on success) / `run` (foreground, llama-swap; the default mode) / `print` (GPU-free argv — the unit-test seam). `RAD_FILE` required for start/run/print; `IMAGE` default `stilldeadcode/radiance:1.11.0`; knobs `PORT`, `CONTAINER_NAME`, `SERVED_NAME` (served alias), `EXTRA_ARGS`, `WAIT`, `EXCLUSIVE` (gpu_exclusive.sh path — override in unit tests). Per-model starters: `start_ornith_35b_vllm_rad.sh` (Ornith 1.5, renamed from `ornith_rad_mtp.sh` 2026-11-08) + `start_qwen38_27b_iq4r-l-v4_rad.sh` (IQ4R-L-V4, 2026-11-08) — thin wrappers over the daemon modes (27B values from `stack/serve/27b.conf`). Native Radiance has its own CLI — `serve_vllm.sh` does not drive it.
- Models: `.rad` files in `/mnt/Lin1/work/radiance/models/<org>__<repo>@<rev8>/` (HF snapshot + README with speed table, serve flags). **Each model README states "Needs radiance >= x" — that is a hard gate on the new tag before boot.**
- Radiance flags differ from vLLM: `--model /models/<rad>`, `--reasoning-effort-map high=xhigh` (template rejects OpenAI `high`), heretic adds `--reasoning-effort medium` + `--max-num-batched-tokens 2048`, KV fp8, `--gpu-headroom-mib` (default 96). **Re-check `--help` on every new tag — flags change.**
- **Headroom issue is LIVE** (`docs/guides/vllm/known-issues.md`): default headroom 96 leaves 113 MiB free at peak (MEASURED, 1.16.0) and crashed the desktop once — "not desktop-safe as measured". **The launcher has no VRAM watchdog** (unlike the vLLM track): sample VRAM during boot (iron rule 7) and abort on dip; ornith starter uses `--gpu-headroom-mib 596`, optional `EXTRA_ARGS="--gpu-headroom-mib 2048"` (unmeasured).
- Boot is fast (~55 s MEASURED; no per-tag compile cache, unlike Sly). `HIP_FORCE_DEV_KERNARG=0` is set by `serve_radiance.sh` (else random MEMORY_FAULT).
- Knowledge base: `docs/guides/vllm/` (same KB; Engines table row "native Radiance") · upgrade log: `stack/serve/radiance/UPGRADES.md` (append-only)
- Launchers (amd-private, thin — source `_lib.sh` + `27b.conf` and end in the shared `rad_run` tail): `../amd-private/clients/claude/claude-rad-{mxfp4,heretic,iq4rlv4}.sh` (iq4rlv4 = IQ4R-L-V4, needs image ≥1.17.0; spec-decode A/B twins `claude-rad-iq4rlv4-{dflash,nospec}.sh` differ only in `--num-speculative-tokens`). Dedicated server starters live in `stack/serve/radiance/start_*_rad.sh` (server lifecycle: start/stop/status/logs, VRAM floor, alias). Manual A/B: `IMAGE=stilldeadcode/radiance:<tag> ./claude-rad-<x>.sh`
- Current (2026-11-08): 1.11.0 = qwen3.8-27b `.rad` + heretic (needs ≥1.2.3) · 1.16.0 = Ornith 1.5 `.rad` — re-read the launcher/starter lines for truth
- **IQR ladder for Qwen3.8-27B is prebuilt on HF** — `StillDeadcode/qwen3.8-27b-iqr-v4` (15 `.rad`: iq2r-v4 … iq8r-v4 incl. -l/-s mixes; `qwen3.8-27b-iq4r-s-v4.rad` 16.5 GB, `iq3r-s-v4` 13.2 GB, `iq4r-v4` 17.6 GB, `iq4r-l-v4` 18.7 GB). **Requires radiance newer than 1.16.0** (1.16.0 and older refuse these files) → a ≥1.17.0 upgrade is the prerequisite for any IQR comparison. ≤IQ5R fits one 32 GB card with long-context headroom; card's one-card serve example: `--max-model-len 200000 --kv-cache-dtype fp8 --max-num-seqs 8`. Source-measured (their TP1): IQ4R-S-V4 decodes one stream 4 % faster than the MXFP4 checkpoint at ~6× lower KL (0.00643 vs AWQ MXFP4 0.03824); IQ3R-S-V4 faster at every concurrency. Depth: `docs/IQR.md` in `src/<tag>/` + `radiance.stilldeadco.de/whitepapers/iqr-v4.pdf`.

## Process

1. **Status.** Previous tag = the `IMAGE=` default in `serve_radiance.sh` / the relevant starter, or the launcher's `IMAGE=` line. No tag given → check Codeberg releases for the newest. Newest == previous → report "up to date", stop.
2. **Investigate improvements (read-only fetch, no GPU — before any decision).** **There is no release-notes page** — the repo is release-snapshot style (one squashed commit per version): `git clone --branch v<tag> --depth 1 https://codeberg.org/StillDeadcode/radiance /mnt/Lin1/work/radiance/src/<tag>` (only if missing; old checkouts stay), then `git fetch --depth 1 origin v<old-tag> && git tag v<old> FETCH_HEAD` (depth 1 is enough — snapshot repo, you only need the two tag blobs) and read the change via `git diff v<old>..<tag>` + docs/README in `src/<tag>/` (grep `kld|divergence|quality` for quality claims). Check each model README's "Needs radiance >= x" against the new tag.
3. **Decision gate — show, then WAIT for the user to choose: continue (upgrade) or skip.** Present: (a) model gate — fail fast if "Needs radiance >= x" is not met; (b) what changed — new/changed/removed flags, defaults, kernel/quality changes; (c) **user-visible effects** — quality/KLD (source's measured numbers; applies to OUR model? config needed?), speed, VRAM/headroom; (d) risk (flag renames break the launchers' `EXTRA_ARGS`; headroom default changes); (e) recommendation. If the user skips → log the outcome (step 10) with what was shown + the reason, stop. Nothing GPU-touching before the decision.
4. **Validate (no GPU, post-GO, pre-boot — "make sure it will be successful").** Flag-table diff: per tag `git show <tag>:core/config.cpp | grep -oP '\{ "--[a-zA-Z0-9-]+' | LC_ALL=C sort -u` → `comm -23` old vs new — **a removed flag = launcher `EXTRA_ARGS` break risk** (if a launcher uses it, stop and report); confirm every launcher flag (read the `EXTRA_ARGS`/starter lines) is present in the new tag; diff the launcher flags' help/defaults (a default change is a behavior change — quote it). Confirm each `.rad` exists with magic `RAD1\2` + size (rule 7: measured, not assumed). Step 2's model gate must hold; RAD format v2 unchanged → existing `.rad` load as-is, no re-convert.
5. **Install.** `docker pull stilldeadcode/radiance:<tag>` ("Image is up to date" = done; skip if already pulled). Never `docker rmi` without explicit user ask.
6. **Smoke.** `gpu_exclusive.sh` (already inside `start`) → `IMAGE=<new> RAD_FILE=<rad> PORT=<port> serve_radiance.sh start` → `/health` → one short generation via curl → **watch VRAM during boot** (no watchdog: `vram_sampler.py` or amd-smi; abort on dip below headroom + desktop share) → `PORT=<port> serve_radiance.sh stop` (silent on success; last log kept in `stack/serve/var/servers/<port>.log`) → verify port free + VRAM idle (iron rule 14).
7. **Bench vs previous.** Boot the new tag; `bench/perf/engine-bench/run.sh` (drives `capture_engine.py probe`; `CAMPAIGN_DIR=campaigns/perf/<stamp>-radiance<tag>-<slug>` required; prompt fixture from `bench/workloads/build_prompt.py`) at ≥4 depths bounded by the model's ctx. Log-log fit: quote per-depth decode/prefill t/s beside exponent + R² (iron rule 16). Baseline = the previous tag's MEASURED row in `docs/guides/vllm/versions.md` (stale → re-measure first).
8. **Verdict + user proof (mandatory).** Show per-depth table + verdict (table below). User manually tests (`IMAGE=<new> ./claude-rad-<x>.sh`). **Promote only on explicit user OK after bench proof + manual test — never auto-promote.**
9. **Promote** (after user OK): `IMAGE=` default in `serve_radiance.sh` / starter → new tag, old tag moved into a rollback comment (existing pattern). `versions.md`: new MEASURED row + citation (iron rule 1). `known-issues.md`/`settings.md` where the notes warrant (e.g. headroom status). The launcher `IMAGE` pins move with the default: `clients/claude/claude-rad-mxfp4.sh` and `claude-rad-heretic.sh` (they copy `serve_radiance.sh`'s default so `rad_run` can check it before `free_gpu`).
10. **Log — every terminal outcome**, promoted / skipped / rejected / boot-failed / rolled back: append to `stack/serve/radiance/UPGRADES.md` — date · from→to · what changed · measured delta + campaign citation · verdict · action · rollback (old tag still local + exact `IMAGE=` to revert).
11. **Present** in this order: summary table; conclusion (2–4 sentences); recommendation + campaign path; **then the per-depth detail tables** — MUST NOT omit or summarize them away.

## Verdict → action

| Verdict | Meaning | Action |
|---|---|---|
| IMPROVEMENT | ≥1 depth ▲, no ▼ | step 8 (user proof), then promote on OK |
| NEUTRAL | all depths within n=2 noise | step 8 — user still decides (fixes may justify it) |
| REGRESSION | ≥1 depth ▼ (≥5% at n=1) | default: reject; show ▼ depths + offer n=2 re-run; user decides |
| BOOT_FAIL | load failure / VRAM dip below headroom / Memory Fault / device loss | FORBIDDEN to promote; cite `known-issues.md`, fix (often `EXTRA_ARGS="--gpu-headroom-mib …"`), retry |
| NO-BASELINE | no recent MEASURED row for the previous tag | measure the previous tag first (or record a fresh baseline row; do not promote) |

## Known landmines (this track)

- Default `--gpu-headroom-mib 96` left 113 MiB free at peak (1.16.0, MEASURED) and **crashed the desktop** — desktop is not safe by default; the ornith starter uses 596, `2048` is the unmeasured recommended alternative (known-issues.md).
- Radiance claims **all free VRAM minus headroom** whatever `--max-model-len` is — KV cache takes the rest; a "fits in ctx" assumption is not a VRAM proof.
- `.rad` vs HF checkpoint: native Radiance loads `.rad` only (Sly/vLLM loads HF only) — pointing it at an HF dir crash-loops (15 restarts seen).
- Flag renames between tags are common — a launcher `EXTRA_ARGS` that booted on the old tag can fail on the new one; always diff `--help`.
- 1.16.0 Ornith numbers (MEASURED): decode 219.8/205.0/174.5 tok/s at 10k/50k/100k, prefill 13,059/8,029/5,301 tok/s; VRAM peak 32,511 MiB.
